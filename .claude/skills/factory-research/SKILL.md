# Исследование темы

Необязательный этап (спека 2026-08-02 §2, §8): гейта нет
(`factory.py check --stage research` открыт всегда — в `STAGE_REQUIRES["research"]`
пусто), чекпоинта нет. Вызывается явно, когда тема требует фактуры (реальные
места, история, техника, специфический сеттинг), а не при каждом проекте.

## Что делаешь

1. Прочитай `project.json` (`theme`, `type`, `audience`) — это предмет поиска.
2. Сделай НАСТОЯЩИЙ веб-поиск (`WebSearch`/`WebFetch` или другой доступный
   поисковый инструмент). Это закрытое решение спеки (§14, «закрыто решением
   пользователя 2026-08-02»): нельзя подменить поиск знаниями модели — они
   могут быть устаревшими или недостаточными для нишевой темы, а весь смысл
   этапа в том, что источник — реальный интернет, а не память Claude.
3. Собери выжимку: факты, которые пригодятся `factory-story` и `factory-script`
   (сеттинг, терминология, референсы стиля, реальные детали) — с указанием
   источников (URL или названием).

## Что написать

`research.md` — в КОРНЕ проекта (`projects/<проект>/research.md`), НЕ в
`bible/`; так его ищет `factory.py status` (`_project_artifacts` проверяет
`project_dir / "research.md"` отдельно от `bible/`). Frontmatter:

```yaml
---
kind: research
status: draft
---
```

Тело — короткая выжимка по пункту 3. Это входные данные для этапа 3
(`factory-story`), а не отдельный публикуемый документ — не растягивай.

## После записи

1. Закоммить сразу после записи (это база для будущего `factory.py diff`,
   если человек потом что-то в файле поправит):
   ```bash
   git add <проект>/research.md
   git commit -m "draft(preprod): research <проект>"
   ```
   (`<проект>` — тот же путь, что передаётся в `--project`, например
   `projects/pilot`; в CLI-командах ниже путь к артефакту всегда указывается
   ОТНОСИТЕЛЬНО папки проекта, а не от корня репозитория — это два разных
   пространства путей, не перепутай.)
2. Дайджест не нужен (чекпоинта нет) — но коротко доложи, что нашёл и чего не
   удалось найти, прежде чем передать управление дальше (человеку или
   `/factory`).
3. Одобрение необязательно: ни один гейт не проверяет `status` этого файла
   (`DEPENDS_ON["research"]` в `scripts/factory/preprod.py` пуст, и никакой
   другой этап на `research.md` не ссылается). `factory.py status` всё равно
   покажет его в общей таблице, раз файл существует. Если хочешь зафиксировать
   выжимку как финальную, одобрить можно, но эта команда — только человека:
   ```bash
   python scripts/factory.py approve --project <проект> research.md
   ```
   Как и везде в конвейере: `status: approved` проставляет ТОЛЬКО эта команда,
   не скилл.
