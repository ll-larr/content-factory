# Персонажи серии

## Как читать гейт этого этапа (важно, нетипично для остальных этапов)

```bash
python scripts/factory.py check --project <проект> --stage characters --episode <ep>
```

В отличие от остальных этапов, эта команда НЕ отличает «твоя работа ещё не
сделана» от «стоп, ничего не делай» — она использует ровно ту же функцию
(`factory/preprod.stage_gate("characters", ep)`), что и платная генерация
референсов (`generate_batch.py --stage characters`). Поэтому читай проблемы по
СМЫСЛУ, а не просто по факту, что список не пуст:

- проблема про `episodes/<ep>/script.md` (не существует / не одобрен /
  изменён после одобрения) — настоящий блокер: сценарий ещё не готов,
  останавливайся и ничего не пиши, ровно как на любом другом этапе;
- проблемы про `bible/characters/<имя>.md` («не существует», «не одобрен
  (status: draft)», «нет блока canonical:appearance») — это НЕ блокер, а
  список того, что нужно написать или доработать ПРЯМО СЕЙЧАС. Гейт «закрыт»
  именно потому, что твоя часть работы ещё не сделана — так и задумано:
  ровно этот же гейт, когда он откроется, разрешит `generate_batch.py`
  потратить деньги на референс, — значит, до тех пор карточка обязана быть
  готова и одобрена человеком;
- если список проблем пуст — все карточки состава уже одобрены; переходи
  сразу к разделу «Фаза 2» ниже, писать текст не нужно.

Состав серии узнаёшь либо из frontmatter `episodes/<ep>/script.md` (поле
`characters`), либо прямо из имён персонажей, названных в проблемах гейта.

## Фаза 1 — карточки (текст, бесплатно)

Выполняется, когда среди проблем гейта есть хотя бы одна про
`bible/characters/`.

1. Прочитай `episodes/<ep>/script.md` (состав и то, как персонажи ведут себя
   в серии), `bible/idea.md`, `bible/style-guide.md`, `bible/craft-notes.md`
   (если есть — группы «Персонажи», «Визуальные описания»).
2. На каждого персонажа состава, чья карточка ещё не одобрена, напиши или
   перепиши `bible/characters/<Имя>.md`. **Имя файла — БУКВАЛЬНО то же, что в
   поле `characters` сценария** (без транслитерации и нормализации: гейт и
   `generate_batch.py` ищут файл по точному совпадению строки).

   Frontmatter:
   ```yaml
   ---
   kind: character
   name: <Имя>
   status: draft
   voice: <тембр словами — например «низкий хриплый баритон, лёгкая одышка»;
     аудиопроба НЕ генерится, Фаза 4 (звук) отложена, поле — задел на неё>
   ---
   ```
   (`name` не обязателен коду — без него `factory/preprod.dependencies` берёт
   имя из `art.path.stem`, то есть из имени файла; но пиши явно, дешевле для
   человека, читающего карточку отдельно от файловой системы.)

   Тело: роль в серии, характер (черты, мотивация, как говорит) — и
   обязательный блок:
   ```markdown
   <!-- canonical:appearance -->
   orange tabby cat, white chest patch, blue spacesuit
   <!-- /canonical:appearance -->
   ```
   Только внешность, по-английски, без слов про настроение или сюжет — этот
   текст ДОСЛОВНО уйдёт в промпт каждого кадра с персонажем (спека §10). Без
   блока гейт `storyboard` не пропустит серию
   (`factory/preprod._cast_problems` вызывает `has_canonical(card,
   "appearance")` явно).

3. Закоммить карточки сразу после записи, до правок человека:
   ```bash
   git add <проект>/bible/characters/<Имя1>.md <проект>/bible/characters/<Имя2>.md
   git commit -m "draft(preprod): character cards <ep> <проект>"
   ```
4. Дайджест: на каждого персонажа — имя, роль, характер одной строкой; что
   изменилось после прошлых правок пользователя (`factory.py diff --project
   <проект> bible/characters/<Имя>.md`, если карточка уже существовала);
   открытые вопросы. Останови работу здесь.
5. **Не проставляй `status: approved` сам.** Человек одобряет каждую карточку
   отдельно:
   ```bash
   python scripts/factory.py approve --project <проект> bible/characters/<Имя>.md
   ```

## Фаза 2 — референсы (деньги)

Начинай эту фазу только когда гейт из первого раздела ОТКРЫТ (все карточки
состава одобрены). Это единственные деньги во всей первой половине конвейера
(спека §9).

1. Если `project.json.autonomy == "full"` — сначала бюджет, ДО запуска
   генерации (процедура и обоснование — в `.claude/skills/factory/SKILL.md`,
   раздел «Бюджет»; кратко: `echo n | generate_batch.py ...` даёт смету без
   траты денег, затем `factory.py budget --estimate <число>` решает, можно ли
   тратить).
2. Смета и подтверждение (если бюджет уже проверен или `autonomy` не `full` —
   спрашивай подтверждение как обычно):
   ```bash
   python scripts/generate_batch.py --project <проект> --episode <ep> --stage characters
   ```
   Выведет `СМЕТА: N генераций, ~X <единица> (characters, провайдер …,
   модели: …).` и спросит `Запустить? [y/N]`. Отвечай `y`, если смета
   разумна (или уже прошла проверку бюджета), либо `--yes` для
   неинтерактивного запуска.
3. Дождись `generated` и прими решение по каждому референсу (обычный цикл
   ревью второй половины конвейера, рубрика брака — базовая спека §9):
   ```bash
   python scripts/review.py --project <проект> list --status generated
   ```
   Посмотри `bible/characters/<имя>-ref.png` (можно прочитать как изображение)
   и сверь с каноническим блоком внешности и со стайл-гайдом. Дальше:
   ```bash
   python scripts/review.py --project <проект> accept bible/characters/<имя>
   # или, если брак:
   python scripts/review.py --project <проект> reject bible/characters/<имя> --reason "..."
   ```
   Item id для персонажа — ровно `bible/characters/<имя>` (без `.md` и без
   `-ref.png`; так его формирует `generate_batch.build_jobs`). Лимит
   переотправки — `project.json.max_rejections` (дефолт 2); после лимита
   `generate_batch.py` сам остановится и попросит решения человека —
   `review.py requeue bible/characters/<имя>` возвращает в очередь.
4. Когда референс каждого персонажа состава принят (`done` или
   `accepted_with_notes`) — финальный дайджест: карточка + референс на
   каждого; если `autonomy` был `auto_approve`/`full`, явно отметь, что текст
   карточки одобрил сам. Дальше — `/factory-storyboard` или возврат в
   `/factory`.

**Итог этапа — ДВА независимых утверждения человека**, а не одно: текст
карточки (`factory.py approve`) и картинка референса (`review.py accept`).
Автономные режимы (`auto_approve`/`full`) автоматизируют только первое.
Ревью референса Claude делает сам, зрением, по рубрике брака — вне
зависимости от `autonomy`, это не пауза-чекпоинт, а обычная проверка
качества, как и во второй половине конвейера (кадры, отрезки).
