# Раскадровка (shots.json)

## Перед работой

1. Проверь гейт. Закрыт — остановись и покажи причины, ничего не пиши:
   ```bash
   python scripts/factory.py check --project <проект> --stage storyboard --episode <ep>
   ```
   Закрыт обычно значит: сценарий или стайл-гайд не одобрены, либо у
   персонажа состава серии нет одобренной карточки или в ней нет блока
   `canonical:appearance` (`factory/preprod._cast_problems` проверяет это
   явно для карточек — см. следующий пункт про то, чего она НЕ проверяет).
2. Прочитай `episodes/<ep>/script.md` (биты серии — по одному будущему
   отрезку на бит), `bible/style-guide.md`, `bible/craft-notes.md` (если
   есть — группа «Визуальные описания»).
3. Гейт уже проверил за тебя, что `bible/style-guide.md` одобрен И несёт блок
   `<!-- canonical:style -->…<!-- /canonical:style -->`, а каждая карточка
   персонажа состава серии — блок `canonical:appearance`. Если `check` открылся,
   разворачивать плейсхолдеры есть чем.

## Что написать

`episodes/<ep>/shots.json` — обычный JSON в формате `scripts/factory/shots.py`
(точный контракт `frames`/`segments` — README, раздел «Конфигурация
проекта»). **Это НЕ YAML-frontmatter артефакт**: у него нет `kind`/`status`.
`factory.py approve` и `factory.py feedback` на нём работать не будут
(`load_artifact` требует YAML-шапку, которой в чистом JSON нет, — вызов
упадёт `ArtifactError`) — не обещай их пользователю и не пытайся сам
проставить в файл поля `status`/`kind`, они там не читаются никаким кодом.

Число кадров и отрезков — по битам сценария; длина отрезка —
`segment_seconds` из `project.json.quality_mode` (`high` = 5с, `budget` =
10с).

Промпт каждого кадра пишется ПЛЕЙСХОЛДЕРАМИ, а не копией текста канонических
блоков (спека §10):

- `{{style}}` — обязателен в КАЖДОМ кадре без исключения, без аргумента;
- `{{char:<имя>}}` — на каждого персонажа, присутствующего именно в этом
  кадре; `<имя>` — то же имя, что в `characters` сценария и в имени файла
  карточки (`bible/characters/<имя>.md`);
- `refs` кадра — список путей `bible/characters/<имя>-ref.png` (относительно
  папки проекта) на каждого персонажа, объявленного через `{{char:...}}` в
  этом кадре. Референс должен существовать и быть принят ревью на этапе 5 —
  это проверяет гейт этапа `storyboard`, один и тот же у `factory.py check` и
  у `generate_batch.py`, так что на этапе написания `shots.json` просто
  подставляй путь по имени, не проверяй статус манифеста сам.

Копировать текст канонических блоков в промпт нельзя — это осознанное решение
спеки (§10): плейсхолдер даёт дословность кодом, а не дисциплиной копирования,
и экономит тысячи токенов на серию из ~60 кадров.

Отрезки (`segments`) — `start_frame` (обязателен), `end_frame`
(НЕОБЯЗАТЕЛЕН) и промпт движения обычным текстом.

**По умолчанию `end_frame` НЕ ставь.** Отрезок без него — движение внутри
одного плана: видеомодель получает первый кадр и никуда не интерполирует.
Пара кадров РАЗНЫХ планов заставляет её перетекать из локации в локацию —
живой прогон 2026-09-03 дал дом, вырастающий из ниоткуда, лампу, чинящуюся
саму, и птицу с двумя клювами. Стык планов — работа монтажа, а не видеомодели.
`end_frame` уместен ровно там, где оба кадра принадлежат ОДНОМУ плану и
переход между ними физически непрерывен (одна и та же камера, одна локация).

Промпт движения описывает, что меняется ВНУТРИ плана за отрезок: что делает
персонаж, куда идёт камера. Слова «cut», «затем», смена локации в промпте
отрезка — признак того, что вместо одного плана описаны два. **Плейсхолдеры в промпт отрезка не подставляй** —
код их там не разворачивает (`build_jobs` для стадии `segments` берёт промпт
как есть), и случайный `{{...}}` уйдёт провайдеру буквально; отдельный гейт в
`generate_batch.py` ловит это отдельно (код 2, «ПЛЕЙСХОЛДЕРЫ В ПРОМПТЕ
ДВИЖЕНИЯ»), но проще не создавать проблему.

## После записи

1. Закоммить `shots.json` сразу после записи:
   ```bash
   git add <проект>/episodes/<ep>/shots.json
   git commit -m "draft(preprod): shots <ep> <проект>"
   ```
2. Чекпоинта нет (спека §8: «нет — дальше гейт трат»). Ничего не одобряется и
   не проставляется. Доложи, что `shots.json` написан, и что дальше начинается
   платная генерация кадров/отрезков — она в скоуп этого скилла не входит.

## Необязательная самопроверка перед докладом

Отдельной команды «только проверить промпты» нет — проверка (`prompt_problems`)
живёт внутри `generate_batch.py` и срабатывает ДО сметы. Прогони генерацию в
режиме отмены: проверка отработает, а деньги не потратятся, потому что до
подтверждения дело не дойдёт.

```bash
echo n | python scripts/generate_batch.py --project <проект> --episode <ep> --stage storyboard
```

**Никогда не подставляй здесь `--yes`** — это запустит платную генерацию.
Код 2 с «ПРОМПТЫ НЕ ПРОШЛИ ПРОВЕРКУ» или «ПЛАН СЪЁМКИ НЕ ПРОШЁЛ ПРОВЕРКУ» —
почини `shots.json` и повтори. Код 3 «ГЕЙТ ЗАКРЫТ» — дело не в раскадровке:
не закрыт предыдущий этап (чаще всего не принят референс персонажа), проверить
можно и без запуска платной стадии — `factory.py check --stage storyboard`.
Код 1 «Отменено.» после чистой сметы — промпты годны, дальше дело платной
генерации, до которой этот скилл не доходит.
