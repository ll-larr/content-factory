# Контент-завод, автономный режим

Ведёт проект по `research → bible/ → episodes/*/script.md → персонажи →
shots.json` для ВСЕХ эпизодов по порядку (спека §7).

`research` возвращается ТОЛЬКО у жанра, объявившего `requires_research: true`
(сейчас это познавательное): там источники — первая фаза, а библия, написанная
раньше них, выдумка, которую придётся переписывать. У остальных жанров
исследование остаётся необязательным и вне резолвера: нужно — вызови
`/factory-research` отдельно, до первого запуска `/factory`.

## Цикл

1. Спроси следующий шаг:
   ```bash
   python scripts/factory.py next --project <проект>
   ```
   Вывод `всё закрыто — следующего шага нет` — работа кончена: доложи и
   остановись. Иначе вывод — `<stage>` или `<stage> <ep>`.

2. Вызови скилл этапа по таблице:

   | stage | скилл |
   |---|---|
   | `research` | `/factory-research` — только там, где жанр его требует |
   | `story` | `/factory-story` (если `bible/idea.md` ещё нет — сперва `/factory-pitch`) |
   | `script` | `/factory-script` (episode = `<ep>` из вывода `next`) |
   | `factcheck` | `/factory-factcheck` (episode = `<ep>`) — только у жанра с `fact_check: required` |
   | `characters` | `/factory-characters` (episode = `<ep>`) |
   | `storyboard` | `/factory-storyboard` (episode = `<ep>`) |
   | `storyboard_generate` | `generate_batch.py --stage storyboard` (платно) |
   | `segments` | `generate_batch.py --stage segments` (платно) |
   | `audio` | нет плана — `/factory-audio`; план есть — `generate_batch.py --stage audio` (платно) |
   | `foley` | `generate_batch.py --stage foley` (платно) |
   | `lipsync` | `generate_batch.py --stage lipsync` (платно) |
   | `render` | `scripts/render.py` (бесплатно) |

3. Скилл этапа сам останавливается на своём чекпоинте (или сразу, если
   чекпоинта нет — `storyboard` без чекпоинта). На чекпоинте действуй по
   `project.json.autonomy` (поле читай напрямую из файла — ни одна команда
   CLI его не печатает; отсутствие поля в JSON = `checkpoints`, дефолт):

   | autonomy | на чекпоинте |
   |---|---|
   | `checkpoints` (дефолт) | показать дайджест скилла и **остановиться**, доложить пользователю |
   | `auto_approve` | вызвать `factory.py approve --auto` на каждый написанный текстовый артефакт, идти дальше |
   | `full` | то же, что `auto_approve`, плюс на платных стадиях тратить без вопроса в пределах `budget_usd` (раздел «Бюджет» ниже) |

   При `auto_approve` и `full` в дайджесте всё равно скажи пользователю, что
   одобрил сам. **Флаг `--auto` обязателен** в этих режимах: он пишет во
   frontmatter `approved_by: auto`, и без него по файлу не отличить решение
   человека от решения машины (спека §7). Ручное одобрение это поле снимает,
   поэтому одобрив что-то сам, человек стирает пометку — так и задумано.

   Для этапа `characters` учти: у него ДВЕ точки одобрения — текст карточки
   (`factory.py approve`) и картинка референса (`scripts/review.py accept`,
   после того как Claude посмотрел на неё). Автономность управляет только
   первым. Референс Claude ревьюит зрением сам, по рубрике брака (базовая
   спека §9), в любом из трёх режимов — это не чекпоинт-пауза, а обычная
   проверка качества, и её нельзя пропускать даже в `full`.

   `next_stage` знает про обе половины: пока референс персонажа состава серии
   не принят ревью, он продолжает возвращать `characters` для этого эпизода и
   в `storyboard` не пускает. То есть повторный вызов `/factory-characters`
   после одобрения текстов — это норма цикла, а не зацикливание: во второй
   заход скилл дойдёт до платной генерации референсов.

   У познавательного жанра точек одобрения сценария тоже две, и порядок
   обратный привычному: сперва `factcheck`, потом `approve`. `next_stage`
   возвращает `factcheck`, когда сценарий НАПИСАН, но не проверен, — это не
   просьба переписать его заново. `factory.py approve` откажет кодом 3, пока
   вердикт проверки не `passed` и её хеш не совпадает с телом сценария.

4. Вернись к шагу 1. Эпизоды идут по порядку (`ep01 → ep02 → …`) и цикл не
   заканчивается на первом — как только `shots.json` эпизода написан,
   `next_stage` сам возвращает `script` следующего эпизода.

   Одно исключение из «по порядку»: серия, у которой референс СГЕНЕРИРОВАН и
   ждёт `review.py accept`, откладывается, и `next_stage` отдаёт текстовую
   работу следующей серии. Ждать здесь нужно человека, а не машину, и
   замораживать бесплатную работу по всему сезону из-за одного непринятого
   референса незачем. Когда актуальной работы не останется, резолвер вернётся
   к отложенной серии сам — так что «характеры ep01» после сценария ep02 это
   не откат, а возврат долга.

## Платная половина

С 2026-09-04 резолвер ведёт до конца: после раскадровки он возвращает кадры,
отрезки, звук, фоли, липсинк и монтаж. Платная работа идёт ВТОРЫМ проходом —
сперва текст всех серий, потом съёмка: бесплатная работа по сезону не должна
ждать, пока досняли предыдущую серию.

**Перед первой платной стадией эпизода покажи человеку ОДНУ смету на весь
остаток**, а не смету каждой стадии по отдельности:

```bash
python scripts/factory.py estimate --project <проект> --episode <ep>
```

Это и есть визуальный чекпоинт: человек видит кадры и общую цену того, что за
ними последует. Дальше стадии идут подряд без отдельных вопросов.

`next` возвращает `None` не только когда всё сделано, но и когда работа ждёт
ЧЕЛОВЕКА: сгенерированные кадры на приёмке машина не сдвинет. Отличать по
`review.py --project <p> list --status generated` — если там что-то есть,
докладывай человеку, а не считай эпизод законченным.

## Бюджет

Потолок держит **код, а не ты**. При `autonomy: full` `generate_batch.py` сам
читает `budget_usd` из `project.json`, вычитает уже потраченное по манифесту и,
если смета не влезает в остаток, возвращает код 3 с расшифровкой — до трат и
несмотря на `--yes`. Просто запускай стадию:

```bash
python scripts/generate_batch.py --project <проект> --episode <ep> --stage characters --yes
```

Код 3 с «БЮДЖЕТ ИСЧЕРПАН» — остановись и доложи, **батч не урезай**: частичный
запуск без предупреждения хуже понятной остановки. Код 1 с «autonomy: full
требует budget_usd» — потолок не задан, это ошибка конфигурации, а не повод
тратить без предела.

Команда `factory.py budget --project <проект> --estimate X` осталась
справочной: ею можно спросить остаток заранее, но полагаться на неё как на
гейт не нужно — гейт уже внутри `generate_batch.py`.

В режимах `checkpoints` и `auto_approve` потолок не применяется: трату
подтверждает человек обычным `[y/N]` (автономность в `auto_approve` относится
к тексту, а не к деньгам).

## Чего не делать

- Не проставлять `approved` в обход `factory.py approve` — ни самому, ни
  редактированием frontmatter руками.
- Не запускать платную стадию при закрытом гейте — коды 2 (модель/промпт не
  прошли валидацию) и 3 (гейт пре-продакшна / потолок бюджета) от
  `generate_batch.py`/`factory.py` обходить нельзя, это отказ, а не
  предложение урезать батч.
- Не продолжать после кода 3 «БЮДЖЕТ ИСЧЕРПАН» от `generate_batch.py` — это
  потолок трат в `autonomy: full`, а не намёк сократить смету.
- Не вызывать `/factory-research` по своей воле там, где `next` его не вернул:
  у жанров без `requires_research` этот этап необязателен, и человек решает сам,
  нужен ли он.
