# Контент-завод, автономный режим

Ведёт проект по `bible/ → episodes/*/script.md → персонажи → shots.json` для
ВСЕХ эпизодов по порядку (спека §7). **Не покрывает этап 2 (research):**
`factory.py next` никогда не возвращает `research` (резолвер `next_stage` в
`scripts/factory/preprod.py` его не знает). Если тема нуждается в
исследовании, вызови `/factory-research` отдельно и заранее, до первого
запуска `/factory`.

## Цикл

1. Спроси следующий шаг:
   ```bash
   python scripts/factory.py next --project <проект>
   ```
   Вывод `всё закрыто — следующего шага нет` — работа кончена: доложи и
   остановись. Иначе вывод — `<stage>` или `<stage> <ep>`.

2. Вызови скилл этапа по таблице:

   | stage | скилл |
   |---|---|
   | `story` | `/factory-story` |
   | `script` | `/factory-script` (episode = `<ep>` из вывода `next`) |
   | `characters` | `/factory-characters` (episode = `<ep>`) |
   | `storyboard` | `/factory-storyboard` (episode = `<ep>`) |

3. Скилл этапа сам останавливается на своём чекпоинте (или сразу, если
   чекпоинта нет — `storyboard` без чекпоинта). На чекпоинте действуй по
   `project.json.autonomy` (поле читай напрямую из файла — ни одна команда
   CLI его не печатает; отсутствие поля в JSON = `checkpoints`, дефолт):

   | autonomy | на чекпоинте |
   |---|---|
   | `checkpoints` (дефолт) | показать дайджест скилла и **остановиться**, доложить пользователю |
   | `auto_approve` | вызвать `factory.py approve` на каждый написанный текстовый артефакт, идти дальше |
   | `full` | то же, что `auto_approve`, плюс на платных стадиях тратить без вопроса в пределах `budget_usd` (раздел «Бюджет» ниже) |

   При `auto_approve` и `full` в дайджесте всё равно скажи пользователю, что
   одобрил сам. **Расхождение со спекой §7**, стоит знать заранее: спека
   обещает, что автоматическое одобрение оставляет пометку в `approved_at`
   файла («иначе по файлу не отличить решение человека от решения машины») —
   но `scripts/factory.py:cmd_approve` такого параметра не принимает, флага
   на это нет вообще, и `approved_at` при автоматическом и ручном одобрении
   получается идентичным. Единственный способ отличить — журнал git-коммитов
   этой сессии; так и объясняй, если человек спросит.

   Для этапа `characters` учти: у него ДВЕ точки одобрения — текст карточки
   (`factory.py approve`) и картинка референса (`scripts/review.py accept`,
   после того как Claude посмотрел на неё). Автономность управляет только
   первым. Референс Claude ревьюит зрением сам, по рубрике брака (базовая
   спека §9), в любом из трёх режимов — это не чекпоинт-пауза, а обычная
   проверка качества, и её нельзя пропускать даже в `full`.

4. Вернись к шагу 1. Эпизоды идут по порядку (`ep01 → ep02 → …`) и цикл не
   заканчивается на первом — как только `shots.json` эпизода написан,
   `next_stage` сам возвращает `script` следующего эпизода.

## Бюджет

Единственная платная стадия в скоупе этого драйвера — референсы персонажей
(`generate_batch.py --stage characters`, спека §9; кадры и отрезки — это уже
вторая половина конвейера, за пределами того, что производит `/factory`).

При `autonomy: full` перед запуском узнай смету у кода, а не считай сам.
Отдельной команды «только смета» нет — `generate_batch.py` печатает её
ПЕРЕД вопросом подтверждения, поэтому получи её так:

```bash
echo n | python scripts/generate_batch.py --project <проект> --episode <ep> --stage characters
```

Это выведет `СМЕТА: N генераций, ~X <единица> (characters, …).`, ответит на
свой же вопрос `n` и завершится кодом 1 («Отменено.») — деньги не потрачены.
Возьми число `X` из этой строки и спроси код:

```bash
python scripts/factory.py budget --project <проект> --estimate X
```

Код 3 — БЮДЖЕТ ИСЧЕРПАН: остановись и доложи, **батч не урезай** (частичный
запуск без предупреждения хуже понятной остановки — так решает спека
буквально). Код 0 — запускай по-настоящему:

```bash
python scripts/generate_batch.py --project <проект> --episode <ep> --stage characters --yes
```

Если `autonomy` не `full`, этот раздел не применяется вовсе:
`factory.py budget` в этом случае сам возвращает код 0 с сообщением «режим не
full — потолок бюджета не применяется» (см. `cmd_budget` в
`scripts/factory.py`) без проверки остатка — решение тратить или нет остаётся
на обычном подтверждении `[y/N]` у `generate_batch.py` (в `auto_approve` это
подтверждение всё равно спрашивается — автономность там относится к тексту, а
не к деньгам).

## Чего не делать

- Не проставлять `approved` в обход `factory.py approve` — ни самому, ни
  редактированием frontmatter руками.
- Не запускать платную стадию при закрытом гейте — коды 2 (модель/промпт не
  прошли валидацию) и 3 (гейт пре-продакшна / потолок бюджета) от
  `generate_batch.py`/`factory.py` обходить нельзя, это отказ, а не
  предложение урезать батч.
- Не продолжать после кода 3 от `factory.py budget` — это потолок трат в
  `autonomy: full`, а не намёк сократить смету.
- Не вызывать `/factory-research` из цикла — этот этап вне резолвера `next`,
  запускается человеком отдельно, до `/factory`.
