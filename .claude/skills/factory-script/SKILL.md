# Сценарий серии

## Перед работой

1. Проверь гейт. Закрыт — остановись и покажи причины, ничего не пиши:
   ```bash
   python scripts/factory.py check --project <проект> --stage script --episode <ep>
   ```
   Закрыт (код 3) почти всегда значит, что `bible/idea.md` и/или
   `bible/season-arc.md` ещё не одобрены (`STAGE_REQUIRES["script"]` в
   `scripts/factory/preprod.py`) — покажи причины построчно как есть, это уже
   человекочитаемый текст (`не одобрен (status: draft)` / `изменён после
   одобрения — перечитай и одобри заново` и т.п.).
2. Прочитай `bible/idea.md`, `bible/season-arc.md` (дуга именно ЭТОЙ серии
   внутри сезона), `bible/craft-notes.md` (если есть — группы «Сюжет»,
   «Диалоги»), `project.json` (`audience`, `episode_duration_sec`,
   `quality_mode`). Если это не первая серия сезона — прочитай также сценарии
   уже написанных серий (`episodes/ep01/script.md` и т.д.), чтобы не
   противоречить уже введённым персонажам и сюжетным ниточкам.

## Что написать

`episodes/<ep>/script.md`, `kind: script`, `status: draft`.

**Обязательно объяви состав серии** полем `characters` во frontmatter:
```yaml
---
kind: script
status: draft
characters: [Мурзик, Барсик]
---
```
Список — точные имена (регистр и написание важны буквально: гейт ищет файл
`bible/characters/<имя>.md` по точному совпадению строки, без нормализации
или транслитерации). Эти же имена станут аргументом `{{char:<имя>}}` в
раскадровке. Гейты этапов 5 и 6 берут состав ИМЕННО из этого поля
(`factory/preprod.episode_cast`), а НЕ поиском имени персонажа по тексту
сценария — спека прямо предупреждает (§4), что поиск подстрокой врёт в обе
стороны: «Мурзик смотрит на фотографию Барсика» записал бы Барсика в
участники, хотя его в кадре нет, а персонаж, упомянутый иначе, не нашёлся бы
вовсе. Пропущенное в `characters` имя означает, что персонаж уйдёт в платную
генерацию кадров БЕЗ карточки и БЕЗ референса, и гейт этого не поймает —
он просто не будет знать, что такой персонаж существует. Серия без
персонажей (заставка, титры) — `characters: []` или поле опущено вовсе.

Тело — сценарий, разбитый на биты по `segment_seconds` секунд (в
`project.json.quality_mode`: `high` → 5с на бит, `budget` → 10с, дефолт
`high` — `factory/project.py:VALID_QUALITY`), один бит на будущий видеоотрезок.
У бита: что происходит, реплики персонажей (только тех, что в `characters`),
метки звуковых событий (заготовка на будущую Фазу 4 — она отложена, сейчас
метки просто фиксируются текстом, ничего не генерят).

Длительность серии — `project.json.episode_duration_sec`. Число битов ×
`segment_seconds` должно сходиться с ней, иначе раскадровка (`shots.json`) не
соберётся 1:1 с планом.

## После записи

1. Закоммить файл сразу после записи, до правок человека:
   ```bash
   git add <проект>/episodes/<ep>/script.md
   git commit -m "draft(preprod): script <ep> <проект>"
   ```
2. Покажи дайджест и остановись: поэпизодный пересказ серии + ключевые
   диалоги + (если это правка черновика — `factory.py diff --project
   <проект> episodes/<ep>/script.md`) что изменилось после прошлых правок
   пользователя + открытые вопросы.
3. **Не проставляй `status: approved` сам.** Одобряет человек:
   ```bash
   python scripts/factory.py approve --project <проект> episodes/<ep>/script.md
   ```
