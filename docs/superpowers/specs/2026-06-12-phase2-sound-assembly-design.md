## 1. Цель и скоуп

Фаза 2 реализует этапы 8–9 пайплайна: озвучка серии (диалоги, диктор, музыка,
SFX) и сборка финального mp4. Все четыре звуковых компонента — в скоупе.
Порядок работ: **сборка первой** (тестируется на готовых артефактах smoke
фазы 1 без новых зависимостей и трат), затем звук, затем интеграция.

Критерий завершения — боевой smoke на `projects/_smoke`: реплика TTS + музыка +
SFX → сведение → сборка с готовым отрезком kling3_0 → mp4 со звуком
(~5–10 кр, траты только с подтверждения пользователя).

## 2. Решения пользователя (зафиксированы, не пересматривать)

1. **Скоуп:** обе части (звук + сборка) в одной фазе, сборка первой.
2. **Провайдер звука:** весь звук через Higgsfield (подход A), с явным планом
   перехода TTS на ElevenLabs при выходе на ≥2–4 серии/мес (§3).
3. **Язык:** основной — английский, опционально русский (Inworld держит оба
   в production-качестве).
4. **Музыка:** генерация (не библиотека треков) — закрывает открытый вопрос
   §16.2 основной спеки.
5. **Учёт фактических списаний** (находки smoke №3–4): отложен, НЕ в фазе 2
   (вместе с пересмотром экономики перед продом).
6. Траты кредитов — только с подтверждением пользователя (как в фазе 1).

## 3. Выбор звукового провайдера

У Higgsfield в том же CLI есть все три аудио-модели (`model list`, type audio):

| Компонент | job_set_type | Смета (cost-валидация) | Под капотом |
|---|---|---|---|
| TTS (диалоги, диктор) | `inworld_text_to_speech` | 2 кр/генерация (не зависит от длины на пробах) | Inworld — №1 TTS Arena, en+ru production |
| SFX | `mirelo_text_to_audio` | 1.25 кр / 5 с | Mirelo text→audio |
| Музыка | `sonilo_music` | 1.88 кр / 30 с | Sonilo |

Параметры: TTS — `prompt` + `voice` (оба обязательны; имя голоса сметой НЕ
валидируется); Mirelo/Sonilo — `prompt` + `duration`.

**Почему Higgsfield, а не ElevenLabs (§11 основной спеки):** ноль новых
зависимостей (тот же `higgsfield_client`, манифест, сметы, ревью, resume),
единый кредитный учёт, дешевле на объёмах фазы 2 и пилота (smoke ~5–10 кр;
озвучка полной серии ~140 кр ≈ $5–10), тогда как ElevenLabs требует отдельной
подписки $5–22/мес ради копеечных объёмов.

**Триггер перехода на ElevenLabs:** при выходе на ≥2–4 серии/мес посимвольный
TTS ElevenLabs становится в ~5–7 раз дешевле за реплику (плоские 2 кр Higgsfield
дороги для коротких реплик; выгодны для длинного закадра). Пересмотреть при
пред-продовой настройке экономики. Архитектурно переход = новая карточка модели
+ новый бэкенд в клиентском слое; сведение и сборка не меняются.

Нативный звук видеомоделей (kling3_0 `sound on`) основным путём НЕ является
(голос неуправляем по персонажам); остаётся экспериментом вне фазы 2 (§16.5).

## 4. План звука: `episodes/epNN/audio.json`

Аналог shots.json — единственный источник правды для скриптов. Пишет
Claude/человек (парсер script.md НЕ строим: этапа 4 ещё нет, YAGNI).

```json
{
  "voice_lines": [
    {"id": "vl-01", "speaker": "cat", "voice": "<inworld-voice-id>",
     "text": "Hello!", "segment": 1, "offset": 0.5}
  ],
  "music_cues": [
    {"id": "mus-01", "prompt": "upbeat cartoon chase, playful orchestral",
     "duration": 30, "segment": 1, "offset": 0.0}
  ],
  "sfx": [
    {"id": "sfx-01", "prompt": "wooden door creaks open",
     "duration": 3, "segment": 2, "offset": 1.0}
  ]
}
```

Поля:

- `id` — уникален в пределах файла (префиксы `vl-`/`mus-`/`sfx-`); под этим же
  id единица живёт в манифесте.
- `speaker` — имя персонажа или `narrator`; информационное поле для ревью
  (голоса персонажей долгосрочно живут в библии — этап 5; в фазе 2 `voice`
  задаётся прямо здесь).
- `voice` — id голоса Inworld, обязателен для voice_lines.
- `duration` — секунды, обязательна для music_cues и sfx (TTS длительность
  определяется текстом).
- **Тайминг:** `segment` (номер существующего отрезка из shots.json) +
  `offset` (секунды от начала отрезка, float ≥ 0). Абсолютные таймкоды НЕ
  хранятся — их вычисляет сведение по фактическим длительностям файлов
  отрезков (ffprobe): t = Σ фактических длительностей отрезков 1..(segment−1)
  + offset. Это защита от «плавания» длин у видеомоделей.

Валидация (новый модуль `scripts/factory/audio_plan.py`, доменная ошибка
`AudioPlanError`, fail-fast до смет): уникальность id, ссылки `segment` на
существующие отрезки shots.json, обязательные поля по типу, `offset ≥ 0`,
`duration > 0`.

## 5. Генерация аудио: стадия `audio` в generate_batch.py

Отдельный tts.py НЕ пишем — расширяем существующий оркестратор:
`generate_batch.py --project ... --episode ... --stage audio`.

- Каждая единица audio.json — item манифеста с типами `voice` / `music` / `sfx`
  (манифест по основной спеке §10 изначально задуман и под аудиофайлы).
- Машина статусов, смета с подтверждением, resume, автоперевод
  `rejected → pending`, лимит `max_rejections` — всё переиспользуется из
  фазы 1 без изменений семантики.
- Ревью — существующий `scripts/review.py` (list/accept/accept-notes/reject/
  requeue); ревьюер слушает файл по пути из манифеста.
- Раскладка файлов: `episodes/epNN/audio/voice/vl-01.<ext>`,
  `.../music/mus-01.<ext>`, `.../sfx/sfx-01.<ext>` (расширение — по факту
  из спайка §6).
- Карточки моделей: `knowledge/audio/inworld_text_to_speech.md`,
  `mirelo_text_to_audio.md`, `sonilo_music.md` по `_template.md`
  (`status: skeleton` до спайка). В `project.json` → `models` добавляются
  ключи `tts` / `sfx` / `music`; `models.py` валидирует по карточкам как
  для image/video.

## 6. Спайк аудио-моделей (первая задача звуковой части)

Бюджет ~6–8 кр, каждая трата с подтверждением пользователя. Выяснить:

1. Каталог голосов Inworld: где брать voice id (доки Higgsfield/веб-UI),
   2–3 пробных генерации разными голосами, включая один длинный текст
   (проверка «2 кр за любую длину») и одну русскую фразу.
2. Формат выходных файлов всех трёх моделей (mp3/wav/m4a, sample rate).
3. Максимальная/допустимая `duration` у Mirelo и Sonilo (cost-валидацией
   бесплатно + одна генерация).
4. Поведение невалидного voice id (ошибка до или после списания).

Результаты — в карточки (`status: verified` + наблюдения), новые факты о CLI —
в `knowledge/higgsfield-cli.md`.

## 7. Сведение: `scripts/mix_audio.py`

Вход: audio.json + принятые ревью аудиофайлы + фактические длительности
отрезков (ffprobe). Гейт: все аудио-единицы эпизода в `done` /
`accepted_with_notes`, иначе список проблем + exit 3 (симметрично гейту
segments фазы 1).

- Реплики и SFX расставляются по вычисленным таймкодам (adelay + amix).
- Музыка — фоном с автоприглушением под репликами (ducking через
  `sidechaincompress`).
- Громкости — разумные константы в коде (без настроек в project.json — YAGNI).
- Предупреждение, если реплика/SFX вылезает за границу своего отрезка
  (информативно, не ошибка).
- Если audio.json отсутствует или пуст — внятное сообщение и завершение без
  выходного файла (сборка тогда идёт без звука, см. §8).
- Выход: `episodes/epNN/audio/mix.m4a`, запись атомарная (tmp → rename).

## 8. Сборка: `scripts/assemble.py`

1. **Гейт:** все отрезки эпизода приняты ревью (`done` /
   `accepted_with_notes`), иначе список + exit 3 — расширение гейта фазы 1
   на отрезки, как и планировалось при дизайне ревью.
2. **Склейка** отрезков по номерам с единой перекодировкой (libx264 + общие
   параметры) — надёжно при разных кодеках источников; stream-copy — будущая
   оптимизация, не сейчас.
3. **Звук:** если `audio/mix.m4a` существует — наложить; если нет — собрать
   без звука с пометкой в выводе (позволяет сдать сборку раньше звука).
4. **Выход:** `episodes/epNN/final/epNN.mp4`, 16:9, запись атомарная.
5. **Контроль длительности ±5%:** факт (ffprobe результата) против плановой
   суммы `len(segments) × project.segment_seconds`; при выходе за предел —
   громкое предупреждение, файл сохраняется, exit 0.

Отступление от §12: контроль против суммы отрезков, а не «заявленной»
длительности эпизода (`episode_duration_sec` относится к этапам 1–5, которых
ещё нет). Шортс-баннер и 9:16 — отложены (в репо нет шортс-проектов).

## 9. Обработка ошибок

- Техсбои генерации — как в фазе 1: ретраи, resume из манифеста, job_id
  фиксируется при сбое.
- Ошибки ffmpeg/ffprobe — падение с понятным сообщением и полной командой
  для ручной диагностики; никаких частично записанных выходных файлов
  (tmp → rename).
- Исчерпание кредитов — остановка с внятным сообщением (как сейчас).

## 10. Тесты

Всё мокается, кредиты не нужны. ffmpeg обязателен в окружении тестов (стоит
через winget, фаза 1).

- Валидация audio.json: все доменные ошибки + happy path.
- Стадия audio в generate_batch на мок-клиенте: смета, статусы, resume, лимит.
- Вычисление таймкодов из segment+offset по фактическим длительностям.
- mix_audio и assemble — интеграционно на крошечных синтетических файлах,
  которые генерит сам ffmpeg (lavfi: `color` + `sine`, <1 с) — реальная
  проверка ffmpeg-пайплайна без больших бинарей в репо.
- Гейты (аудио и отрезки): exit 3 и список проблем.
- Контроль ±5%: предупреждение есть/нет.

## 11. Порядок работ

1. `assemble.py` видео-only + гейт отрезков (тестируется на артефактах smoke).
2. Спайк аудио-моделей (§6) + карточки → verified.
3. `audio_plan.py` (audio.json) + стадия `audio` в generate_batch.py.
4. `mix_audio.py`.
5. Интеграция звука в `assemble.py`.
6. Финальный боевой smoke на `_smoke` (§1) + обновление прогресс-дока.

Процесс — как в фазе 1: superpowers:writing-plans →
superpowers:subagent-driven-development (исполнитель sonnet → spec-ревью haiku
→ quality-ревью sonnet → фиксы отдельным коммитом), тесты строго
`.\.venv\Scripts\python.exe -m pytest -q` из корня, ветка
`phase-2-sound-assembly`.

## 13. Отвергнутые альтернативы

- **ElevenLabs напрямую (§11 основной спеки):** дешевле по юнитам на масштабе,
  но новый аккаунт/ключ/долларовый биллинг и клиент с нуля ради копеечных
  объёмов фазы 2; отложено до триггера §3.
- **Гибрид (TTS внешний, музыка+SFX Higgsfield):** два клиента и два биллинга
  без доказанного прироста качества.
- **Абсолютные таймкоды в audio.json:** разъезжаются при «плавании» фактических
  длительностей отрезков; привязка segment+offset устойчивее.
- **Отдельный tts.py (§11):** дублировал бы манифест/сметы/resume/ревью,
  которые уже есть в generate_batch.py.
