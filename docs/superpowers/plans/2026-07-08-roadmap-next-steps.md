> Для агентов-исполнителей: это РОАДМАП из нескольких независимых подзадач, не единый
> TDD-план. Фаза 1 достаточно конкретна для немедленного исполнения. Фазы 2–3 —
> списки задач с понятным приёмочным критерием, но без пошагового кода (генерация
> живых карточек делается по факту ответа API, не заранее). Фаза 4 — отдельная

> для SFX/музыки пока не исследованы.

живьём почти не проверен» до «дефолтные модели пайплайна verified, монтаж

## Фаза 4 — Генерация звука (ElevenLabs + замена SFX/музыки) — отдельная подсистема
**НЕ начинать писать код по этой фазе без отдельного прохода
`superpowers:brainstorming` → `superpowers:writing-plans`.** Причины:
- Контракт ElevenLabs API не исследован (эндпоинты, аутентификация, тарификация,
  форматы вывода — ничего этого пока нет в `knowledge/`).
- Провайдер для SFX и музыки вообще не выбран — Higgsfield (Mirelo/Sonilo) вырезан,
  замены нет. Это открытый дизайн-вопрос, а не техническая деталь: ElevenLabs делает
  TTS и (возможно) SFX, но не генерирует музыку — нужно либо найти отдельный
  музыкальный провайдер, либо осознанно решить, что музыка не генерируется
  (стоковые треки/без музыки).

Ориентировочный состав будущей работы (не план, а список того, что предстоит решить/сделать):
- Новый провайдер-адаптер `scripts/factory/providers/elevenlabs.py` по образцу
  существующих (`base.py` + `wavespeed.py`/`runware.py`/`openrouter.py` как референс
  структуры, НЕ по видео-контракту — TTS сильно другой).
- Новые карточки `knowledge/audio/elevenlabs_*.md` (замена исторических
  `inworld_text_to_speech.md`/`mirelo_text_to_audio.md`/`sonilo_music.md`, которые
  остаются как референс формата, но в конвейере не используются).
- Решение по SFX/музыке (см. выше) — до него интеграцию TTS можно делать отдельно,
  SFX/музыку — вторым заходом.
- Включение audio-стадии обратно в `generate_batch.py` (сейчас отключена) под новый
  провайдер.
- Живой спайк на реальных ключах ElevenLabs, как это уже делалось для
  video/image-провайдеров — контракт подтверждается генерацией, не документацией.

**Когда дойдём до Фазы 4:** начать с `superpowers:brainstorming` для решения по
SFX/музыке и уточнения объёма (только TTS сейчас, или сразу всё), затем
`superpowers:writing-plans` для детального TDD-плана по образцу того, как был
устроен `2026-06-15-provider-refactor-design.md`.

## Итоговая последовательность
```
Фаза 1 (ops: баланс+ключи → живой Runware → мёрж спайка)
   │
   ├──► Фаза 2 (дефолтные модели verified)          — можно вести параллельно
   └──► Фаза 3 (калибровка дакинга, маленькая)       — можно вести параллельно
             │
             ▼
Фаза 4 (звук: ElevenLabs + SFX/музыка) — отдельная спека, начинается с brainstorming
```

Ничего в Фазах 2–4 не блокируется Фазой 1 технически (модели/монтаж не зависят от
Runware), но по порядку трат и фокуса внимания разумно закрыть спайк первым — он уже
начат и почти закрыт, размазывать его на потом означает валять недоделанное дольше.
