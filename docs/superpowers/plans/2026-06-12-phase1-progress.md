**Решения пользователя (зафиксированы, не переспрашивать):**
1. Ревью делает Claude-режиссёр после каждого батча + пользователь выборочно.
2. Жёсткий чекпоинт: segments ЗАБЛОКИРОВАН, пока кадры отрезков не приняты ревью.
3. Перегенерация: ревьюер правит промпт в shots.json (единственный источник промптов); reject_reason в манифесте — журнал причин.
4. Лимит: **2 отклонения** на кадр → стоп, решение человека.

**Дизайн (драфт, ждёт одобрения):**
- `factory/manifest.py` — новый статус `generated` (= сгенерировано, ждёт ревью):
  `pending → generating → generated | pending(техсбой)`; `generated → done | accepted_with_notes | rejected` (ревью); `rejected → pending`; `accepted_with_notes → pending`; `done` терминален (= принято ревью). Новое поле item: `reject_count` (инкремент при каждом переходе в rejected). `rejected` требует reject_reason (как сейчас).
- `scripts/generate_batch.py` — успешная генерация завершается в `generated`; перед батчем `rejected` с `reject_count < max_rejections` автоматически → `pending` (перегенерация по актуальному shots.json), достигшие лимита пропускаются с громким сообщением; чекпоинт segments: все кадры, на которые ссылаются отрезки, должны быть `done`/`accepted_with_notes`, иначе список + exit code **3** (код 2 остаётся за валидацией модели); `max_rejections` из project.json, дефолт 2; механика общая для кадров и отрезков (гейт на отрезки для сборки — фаза 2).
- `scripts/review.py` — новый CLI для ревьюера (человека и Claude): `list` (item, статус, попытки/отклонения, путь), `accept <ids...>`, `accept-notes <id> --notes "..."`, `reject <id> --reason "..."`.
- Совместимость: старые манифесты с `done` валидны, миграция не нужна. Тесты: переходы машины, гейт, автоперевод rejected→pending, лимит, review-CLI, оркестратор ставит `generated`.
- Отвергнутые альтернативы: разрешить `done → rejected` (рушит семантику для жёсткого чекпоинта); отдельное поле `reviewed` рядом со status (два измерения состояния, YAGNI).
