# Remotion — контракт монтажа

Источник правды для каталога `montage/`. Всё, что специфично для Remotion (версии,
флаги CLI, ограничения, лицензия), живёт ТОЛЬКО здесь и в `montage/` — то же правило
изоляции, что у провайдеров.

Дизайн: `docs/superpowers/specs/2026-08-31-remotion-montage-design.md`.

## Версии (зафиксированы 2026-09-02)

- Node 24.14.0, npm 11.9.0 (`engines.node: >=20` в `montage/package.json`).
- Remotion 4.0.520 — `remotion`, `@remotion/cli`, `@remotion/media-parser`.
- React 19.2, TypeScript 7.0, vitest 4.1.

## Лицензия

Бесплатно для физлиц и компаний **до 3 человек**, коммерческое использование
разрешено. От 4 человек — Company License ($0.01 за рендер при минимуме $100/мес
на тарифе для автоматизации, либо $25/мес за место). Порог считается по размеру
команды, не по объёму рендеров.

`parseMedia` печатает напоминание о лицензии при каждом вызове; глушится параметром
`acknowledgeRemotionLicense: true`. Глушить — не то же самое, что иметь право: при
росте команды до четырёх человек лицензию надо покупать.

## parseMedia — проверено на настоящих выдачах моделей (2026-09-02)

Открытый вопрос спеки §13 закрыт: парсер читает всё, что отдают наши видеомодели.
Проверка бесплатная, на любых локальных файлах.

| Файл | Контейнер | Размер | fps | Длительность | Звук |
|---|---|---|---|---|---|
| `live_p2_vidu_q2_turbo.mp4` (Runware) | mp4 / h264 | **1284×716** | 24 | 5.142 с | aac |
| `live_p2_seedance_2_0.mp4` (WaveSpeed) | mp4 / h264 | 1280×720 | 24 | 5.088 с | aac |
| `live_p2_seedance1_5.mp4` (WaveSpeed) | mp4 / h264 | 1280×720 | 24 | 4.074 с | aac |
| `seg1.mp4` | mp4 / h264 | 1280×720 | 24 | 4.074 с | aac |

Импорт ридера — `import {nodeReader} from '@remotion/media-parser/node'`.

### Что из этой таблицы следует для монтажа

1. **fps у всех выдач — 24, а не 30.** Композиция обязана брать fps из файлов, а не
   из константы: зашитые 30 дали бы ресемпл на ровном месте.
2. **Vidu на Runware отдаёт 1284×716, а не 1280×720.** Внутри одного эпизода работает
   одна модель, поэтому отрезки согласованы между собой; но жёсткий отказ при
   расхождении размеров (решение 2026-08-01) — не теория, разные модели действительно
   дают разные размеры.
3. **У КАЖДОГО отрезка есть своя aac-дорожка.** Прежняя сборка её сознательно
   выбрасывала: в `assemble.py` фильтр `concat=n=N:v=1:a=0` брал только видео, звук
   приходил из сведённого `mix.m4a`. В Remotion это НЕ поведение по умолчанию —
   `<OffthreadVideo>` играет звук дорожки. Поэтому видео отрезков включается только
   с `muted`, иначе звук модели тихо просочится в эпизод поверх сведённого.

## Тихая аудиодорожка в выдаче

Даже когда весь звук выключен (`<OffthreadVideo muted />`, дорожек нет), Remotion
пишет в mp4 дорожку aac из тишины — замерено −91 dB. Прежняя сборка на ffmpeg в
этом случае аудиопотока не создавала вовсе.

Отличие безвредное и скорее полезное: площадки (TikTok, YouTube Shorts) спокойнее
принимают файл с дорожкой, чем без неё. Знать о нём нужно тем, кто проверяет
результат: `has_audio_stream` теперь вернёт `True` для эпизода без звука.

## Команды

Рендер и Studio вызываются из Python (`scripts/render.py`), руками — из `montage/`:

```
npm test                     тесты чистых функций (vitest), часть гейта коммита
npx remotion render <id>     рендер композиции
npx remotion studio          предпросмотр (из Python — только флагом --studio)
```

Ассеты эпизода отдаются рендеру через `--public-dir`, пути внутри листа —
относительные к нему.
