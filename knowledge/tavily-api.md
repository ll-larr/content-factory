# Tavily Search API — контракт

Источник правды для `scripts/factory/providers/tavily.py`. Точные эндпоинт, имена
полей и значения параметров живут ТОЛЬКО здесь и в адаптере (правило CLAUDE.md).

> ⚠️ Контракт собран по официальной документации (docs.tavily.com, 2026-09-07).
> **Живым запросом НЕ проверен**: ключа на машине нет. Что это значит на практике —
> форма ответа и цена в кредитах взяты из доков, а не замерены, поэтому первый
> живой запуск факт-чекера обязан сверить их с фактом и дописать сюда результат.
> Та же дисциплина, что у карточек моделей: каталог провайдера уже дважды соврал
> про цену в разы (gemini_2_5_pro_tts — в 2.4 раза, qwen3 — вдвое).

Зачем этот провайдер вообще: познавательный жанр объявляет `fact_check: required`,
а проверяющему запрещено верить источнику автора — он обязан искать сам. Движок
Claude Code умеет искать своими инструментами, движку «модель по ключу» искать
нечем, и без поискового ключа познавательный жанр ему недоступен.

## Аутентификация
- Заголовок: `Authorization: Bearer ${TAVILY_API_KEY}` (ключ из env, не хардкодить).
- Ключи Tavily начинаются с `tvly-`.

## Поиск
`POST https://api.tavily.com/search`

```json
{
  "query": "<строка запроса>",
  "search_depth": "advanced",
  "max_results": 8,
  "include_answer": false,
  "include_raw_content": false
}
```

Параметры, которые мы используем, и почему именно они:

| поле | значение | почему |
|---|---|---|
| `search_depth` | `advanced` | стоит 2 кредита вместо 1, но отдаёт выдержки глубже одного абзаца; проверка факта по заголовку — не проверка |
| `max_results` | 8 (диапазон 0–20) | правило жанра требует пяти НЕЗАВИСИМЫХ источников; восемь результатов дают запас на пересказы одной новости |
| `include_answer` | `false` | ответ модели Tavily — это ещё один пересказ; проверяющий обязан смотреть на источники сам |
| `include_raw_content` | `false` | полные страницы раздувают промпт в десятки раз; выдержки `content` для сверки факта достаточно |

Прочие поля документации (`topic`, `time_range`, `country`, `language`,
`chunks_per_source`, `include_images`, `auto_parameters`) адаптер не шлёт.
`auto_parameters` отдельно вреден: он молча поднимает цену запроса до 2 кредитов
и переопределяет `search_depth`.

## Ответ

```json
{
  "query": "...",
  "results": [
    {"title": "...", "url": "https://...", "content": "выдержка", "score": 0.93}
  ],
  "response_time": 1.2,
  "usage": {},
  "request_id": "..."
}
```

Адаптер берёт из результата ровно `title`, `url`, `content`, `score` и приводит
их к своей форме (`{"title", "url", "snippet", "score"}`): в промпт проверяющего
не должно уезжать ничего, чего он не обязан читать.

## Цена

| режим | кредитов за запрос |
|---|---|
| `basic`, `fast`, `ultra-fast` | 1 |
| `advanced` | 2 |

Тарифы (docs 2026-09-07): 1000 кредитов в месяц бесплатно; Pay-as-you-go —
**$0.008 за кредит**, то есть $0.016 за один наш запрос в режиме `advanced`.

Порядок цифр для одной серии: проверяющий обычно называет 10–20 утверждений,
это 10–20 запросов, то есть **$0.16–$0.32 за проверку эпизода**. На фоне съёмки
это шум, и экономить здесь на глубине поиска незачем.

Кредиты в смету конвейера (`factory/estimate.py`) не попадают: смета считает
деньги провайдеров генерации по карточкам моделей, а поиск — расход другой
природы и другого счёта. Врать про «сумму за эпизод», подмешивая туда чужую
валюту, хуже, чем не показывать её вовсе.

## Ошибки

| код | что значит |
|---|---|
| 401 | ключ не тот или отозван |
| 429 | кончились кредиты или превышен лимит запросов в минуту |
| 432 / 433 | план исчерпан (по докам; живьём не видели) |

Адаптер заворачивает всё это в `ProviderError` с текстом ответа: проверяющему
нельзя подсовывать пустой список источников вместо ошибки — он тогда честно
напишет «подтверждений не нашлось» и завалит верный факт.
